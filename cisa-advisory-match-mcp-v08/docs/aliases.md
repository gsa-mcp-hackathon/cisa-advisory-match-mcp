## How names affect a result

- Exact names retain priority. The only general normalization is capitalization and whitespace.
- Verified equivalent manufacturer names and manufacturer-scoped product aliases can establish name identity; the original advisory still controls versions and affected status.
- Brand/parent links, historical renames and incomplete component names only produce candidates requiring review. The wrapper does not infer equivalence through chains of acquisitions or aliases.
- A candidate manufacturer relationship cannot unlock a second, nonexact product alias. Confirm both identities before resubmitting. This conservative limit can miss related names.
- Original input labels, advisory labels, applied mapping IDs, source links, catalog version and catalog SHA-256 remain visible. No user input is silently rewritten or persisted.
- Input name hints are clarification aids only. A hint is not an advisory finding or an affected product.

For example, Honeywell International matches Honeywell through a documented manufacturer group. IQ4E alone is a candidate for IQ4E Firmware and requires component confirmation. FactoryTalk View SE and FactoryTalk View ME stay separate. PME resolves within manufacturer scope: Schneider Electric Power Monitoring Expert is different from Emerson PAC Machine Edition.

## Discovery and limits

Discovery searches the supplied manufacturer and up to two additional documented names, with at most two pages per name and twelve requests across the whole call. Original manufacturer searches are considered before additional names. Duplicate searches are shared. Search failures, names not searched, and unexamined advisories are disclosed. The default advisory check budget remains eight, maximum twelve. Input permits up to twenty fictional devices and four manufacturers.

The catalog is a sourced starting set, not all ICS terminology. No fuzzy typo correction, automatic legal-suffix removal, broad punctuation stripping, unreviewed web synonym ingestion, or CPE-based identity inference is implemented. NIST's CPE dictionary is a useful future source of structured identifiers, but it is not imported here. Product families, editions, host/component relationships and unsupported firmware version schemes can still require review. The coverage audit explicitly reports which catalog groups intersect the pinned source snapshot. An observed name is not proof that every source version grammar is supported.

## Maintaining mappings

After editing, rerun `scripts/render_alias_reference.py` with the actual revision timestamp and the offline corpus audit. These scripts count and report the reviewed mappings; they do not approve new ones.

Edit `advisory_matcher/data/aliases.json`, preserving an exact primary-source URL, source title, scope and short rationale for each record. Equivalent groups must mean the same scoped identity, not merely a related product. Use candidate for uncertain history/component relations. Never add a name solely because an SI model suggests it. Avoid contradictory equivalent/candidate pairs, and run the catalog, matching, service and protocol checks after changes. Increase the catalog version when its content changes. Source review dates do not guarantee future ownership or naming.

The complete machine-readable catalog is runtime package data. `alias-reference.csv` supplies the same mappings in a readable table.
